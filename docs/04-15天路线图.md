# 04 · 15 天路线图（技术栈广度版）

> 投入：105h（15 天 × 7h），双人
> 主线：**技术栈广度**
> 交付：本机 `java -jar` 演示
> 前提：功能是技术的**载体**，不是目的。每加一个中间件，必须能回答"不用它会怎样"。

---

## 零、先说一个陷阱

"技术栈广度"最容易走进的坑：**为了用而用**。

| 技术 | 这个项目有自然理由吗 | 判断 |
|---|---|---|
| Redis | ✅ 列表缓存、登录限流、token 黑名单、定时任务分布式锁 | **做，做深** |
| `@Scheduled` | ✅ 重复任务实例生成、过期标记、统计快照 | **做，做深** |
| WebSocket / SSE | ✅ 到期实时推送、多端同步 | **做，做深** |
| RabbitMQ / Kafka | ❌ 没有真正的异步解耦场景 | **不做** |
| Elasticsearch | ❌ 搜索用 MySQL `LIKE` + 索引足够 | **不做** |
| 分库分表 | ❌ 数据量差 4 个数量级 | **不做** |
| 微服务拆分 | ❌ 单体都还没跑顺 | **不做** |

**如果硬上 MQ**，面试官问一句"为什么这里需要消息队列，直接调不行吗"，你答不上来，前面的加分全部变成减分。

**正确姿势**：把 3 个中间件**做深**，比浅尝 5 个值钱。

- Redis：不只是 `get/set`，而是**缓存穿透/击穿/雪崩 + 双写一致性 + 分布式锁**
- `@Scheduled`：不只是 `@Scheduled(cron="0 0 0 * * ?")`，而是**任务幂等 + 分布式锁防重复执行 + 失败重试**
- WebSocket：不只是 `@ServerEndpoint`，而是**连接管理 + 心跳保活 + 断线重连 + 鉴权**

## 一、技术点 → 功能载体 映射（本项目的骨架）

| # | 技术 | 靠什么功能落点 | 你要能讲出什么 |
|---|---|---|---|
| 1 | ThreadLocal 上下文 | 当前用户贯穿 Service 层 | 一次请求的 userId 怎么从拦截器传到 Mapper |
| 2 | MyBatis XML + 动态 SQL | 多条件筛选（状态+分类+标签+关键词+日期范围+排序） | `<if>` / `<where>` / `<foreach>`，以及为什么注解写不下 |
| 3 | PageHelper | 任务列表分页 | 它偷偷改你的 SQL，`PageInfo` 从哪来 |
| 4 | AOP + 自定义注解 | 操作日志表（谁、何时、改了什么） | 切面怎么拿到方法参数，`@Around` 和 `@AfterReturning` 选哪个 |
| 5 | `@Transactional` | 批量完成任务 + 同步统计 | 什么情况回滚、什么情况不回滚（checked vs unchecked） |
| 6 | `@Scheduled` | ① 每日任务实例生成 ② 过期标记 ③ 统计快照 | cron 怎么写、多实例部署为什么会重复执行 |
| 7 | Redis 缓存 | 任务列表 / 统计数据 | 缓存 key 怎么设计、什么时候失效、双写还是删缓存 |
| 8 | Redis 限流 | 登录接口 5 次/分钟 | 固定窗口 vs 滑动窗口，用 `INCR` + `EXPIRE` 怎么做 |
| 9 | Redis 黑名单 | 退出登录 | JWT 无状态的反面：为什么退出需要服务端记一笔 |
| 10 | Redis 分布式锁 | 定时任务防重复执行 | `SET NX EX` 和 Redisson 的区别，锁超时怎么办 |
| 11 | WebSocket | 到期实时推送 + 多端同步 | 为什么不是前端 `setInterval` 轮询，两者各自代价 |
| 12 | 统一异常 + 错误码 | 所有接口 | 一个出口、错误码分段 |
| 13 | 参数校验 | DTO | `@Valid` 失败怎么变成 400 而不是 500 |
| 14 | Swagger / springdoc | 全部接口 | 文档和代码怎么保持同步 |
| 15 | 单元测试 | Service 层核心逻辑 | 怎么 mock Mapper，测什么不测什么 |
| 16 | Excel 导出（POI） | 导出任务清单 | 大数据量怎么流式写 |
| 17 | 文件上传 | 任务附件（本地磁盘） | 为什么不用 OSS（本机演示不需要） |

## 三、15 天路线

### Week 1（D1–D5）：地基与主干

| 天 | 任务 | 当天可验收的产出 |
|---|---|---|
| D1 | 需求冻结 v2 + 技术选型定稿 + **一次建全 8 张表** | `schema.sql` + 需求清单签字 |

## 四、真正的瓶颈：前端产能

后端 32 个接口，前端只有一个人 105h。经验值：**1 个页面 ≈ 8–12h（含联调）**，9 个页面就是 72–108h，**刚好卡满**。

所以前端必须做减法，优先级：

| 优先级 | 页面 | 说明 |
|---|---|---|
| P0 | 登录 / 注册 / 任务主页 | 没它不能演示 |
| P1 | 日历 / 统计 / 回收站 | 体现"完善" |
| P2 | 设置 / 操作日志页 | 日志只存库不展示也行 |
| 砍 | 拖拽排序、主题切换、动画 | 工时黑洞，收益极低 |

**对策**：D2 契约签完，前端立刻开工，不等后端。用 mock 数据（`json-server` 或直接写死数组）先把页面跑起来。

## 五、风险清单

| 风险 | 概率 | 对策 |
|---|---|---|
| Redis 装上但连不上（Windows） | 高 | D4 之前先单独验证 `redis-cli ping`；用 Docker 跑 Redis 最省事 |
| WebSocket 在 Spring Boot 2.7 上配置踩坑 | 中 | D11 整天只做这一件事，别和别的混 |
| 前端页面做不完 | 高 | 按上面 P0/P1 砍；D10 中期演示后立刻砍 P2 |
| 表结构第二次大改 | 中 | D1 一次建全 8 张表，包括暂时不用的 |
| 中间件学不完导致进度崩 | 中 | 每个中间件只给 1 天，做不完就降级（见下） |

### 降级预案

| 中间件 | 原方案 | 降级方案 |
|---|---|---|
| Redis | 缓存 + 限流 + 黑名单 + 分布式锁 | 只留限流 + 黑名单（半天） |
| `@Scheduled` | 三类定时任务 + 锁 | 只留"每日任务生成" |
| WebSocket | 推送 + 心跳 + 重连 | 退回 SSE（简单一半）或前端轮询 |
| 单元测试 | Service 层覆盖 | 只测 3 个核心方法（能讲清"为什么测这三个"就够） |

## 六、和苍穹外卖的对应

| 15 天里做的 | 苍穹外卖里对应 | 超出教程的部分 |
|---|---|---|
| ThreadLocal | BaseContext | — |
| AOP 自动填充/日志 | `@AutoFill` | 自定义注解 + 参数解析 |
| MyBatis XML 动态 SQL | ✅ 一样 | 条件更多 |
| Redis 缓存/限流/锁 | 只用了缓存 | 限流、分布式锁是新的 |
| `@Scheduled` | 有（订单超时） | 幂等 + 锁 |
| WebSocket | 有（来单提醒） | 心跳、重连、鉴权 |
| 单元测试 | 没有 | 全新 |
| 接口文档自己设计 | 现成的 | **全新** |

**结论**：这个项目能覆盖苍穹外卖 70% 的技术点，并且补上教程里没有的三块——**自己设计接口、分布式锁、单元测试**。
