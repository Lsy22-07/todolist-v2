## 零、分级规则（先看这个，否则会误解后面的表）

普通项目按「产品必需程度」分 M/S/C/W。**本项目还要加一条：承载核心技术点的功能，即使产品上不必需，也提到 M。**

因为你的目标是技术栈广度——砍掉一个功能，就是砍掉一个技术点。

例：`操作日志` 产品上可有可无，但它是 AOP 的唯一载体，所以 AOP 部分定 M（存库），展示页面定 C。

## 二、M 级（必须做，每条带「可造的测试用例」）

### 1. 用户注册 / 登录 / 退出

| 验收标准 | 怎么测 |
|---|---|
| 用户名重复时拒绝 | 用 `张三` 注册两次 → 第二次返回 `400`、`msg="用户名已存在"` |
| 密码长度校验 | 密码填 `12345` → 返回 `400`、`msg` 含「6」 |
| 登录成功返回 token | 正确账号密码 → `200`，`data.token` 非空 |
| 密码错误提示一致 | 用户名不存在 / 密码错误 → 都返回「用户名或密码错误」（防用户名枚举） |
| 退出后 token 失效 | 退出后用旧 token 访问 `/api/todos` → `401` |
| 密码不明文存 | 直接查库，`password` 是 `$2a$10$...` |

**承载技术**：BCrypt（苍穹外卖用的是 MD5，这里升级）、JWT 签发与解析、Redis 存 token 黑名单。

---

### 2. 任务新增 / 列表 / 编辑 / 删除 / 勾选

| 验收标准 | 怎么测 |
|---|---|
| 新增必填校验 | 标题为空 → `400`，`msg` 指明字段 |
| 新增成功返回完整对象 | 返回体含 `id`、`createdAt` |
| 列表按用户隔离 | A 登录看到 3 条，B 登录看到 0 条 |
| 列表三态筛选 | `?status=active` 只返回未完成 |
| 编辑只能改自己的 | A 用 PUT 改 B 的任务 id → `404`（不是 403，避免暴露存在性） |
| 删除后列表少一条 | 删完再查，条数 -1 |
| 勾选切换幂等 | 连点两次 → 状态回到原值 |

**承载技术**：三层架构、`@Valid`、ThreadLocal 取当前用户、`@RequestAttribute` vs ThreadLocal 的对比。

---

### 3. 截止时间精确到分

| 验收标准 | 怎么测 |
|---|---|
| 能存到分钟 | 新建 `2026-11-20 18:30`，查库 `due_time = 2026-11-20 18:30:00` |
| 返回不是数组 | 接口返回 `"dueTime": "2026-11-20 18:30"`，不是 `[2026,11,20,18,30]` |
| 前端能回填 | 编辑弹窗打开，时间选择器显示原值 |

**承载技术**：`LocalDateTime` + `@JsonFormat`、MySQL `DATETIME`、时区 `serverTimezone=Asia/Shanghai`。

> ⚠️ 这条必须在 S2 建表时就定，不能等后面改。

---

### 4. 过期任务置顶标红

| 验收标准 | 怎么测 |
|---|---|
| 过期判定 | 截止时间已过且未完成 → 标记为过期 |
| 排序 | 过期未完成排最前，其次按优先级降序，再按截止时间升序 |
| 标红 | 列表里该条截止时间显示为红色 |
| 已完成的过期任务不算 | 勾选完成后，不再标红、不再置顶 |

**承载技术**：排序 SQL 里的布尔表达式、`CASE WHEN`。

---

### 5. 数据隔离（横切所有接口）

| 验收标准 | 怎么测 |
|---|---|
| 每个查询都带 `user_id` | 翻 Mapper，任何 `SELECT` 都不能缺这个条件 |
| 越权访问返回 404 | A 拿 B 的 id 调任意接口 → `404` |

**这是最容易漏的一条**，写完后要专门用两个账号交叉测一遍。

---

### 6. 工程基线（不是功能，但没有它整个项目不成立）

| 项 | 验收标准 |
|---|---|
| 统一响应 | 所有接口返回 `{code, msg, data}` |
| 全局异常 | 故意抛 `RuntimeException` → 返回统一格式，不是 Whitelabel 页 |
| 参数校验 | `@Valid` 失败 → `400`，不是 `500` |
| 当前用户上下文 | 拦截器解析 token 后，Service 层不用传 `userId` 参数就能拿到 |
| 操作日志 | 每个写操作在 `operation_log` 表留一条记录（谁、何时、什么接口、耗时） |

## 三、S 级（应该做，是「功能完善」的主体）

| 模块 | 一句话验收 |
|---|---|
| 分类 | 任务属于一个分类；删分类时，其下任务的 `category_id` 置空（不级联删任务） |
| 标签 | 一个任务可挂多个标签；`?tagId=3` 能筛出带该标签的任务 |
| 子任务 | 父任务显示「3/5 已完成」；删父任务时子任务一起删 |
| 重复规则 | 建一条「每日」任务，第二天 0 点自动出现新实例，且只出现一条（多线程不重复） |
| 搜索筛选 | `?keyword=报告&status=active&categoryId=2&sort=dueTime` 组合生效 |
| 分页 | `?page=1&size=10` 返回 `total`、`pages`、`list` |
| 统计看板 | 首页显示完成率、逾期数、近 7 天每天完成数 |
| 回收站 | 删除的任务进回收站可恢复；恢复后回到原列表 |
| 到期提醒 | 页面开着时，任务到点弹出通知（WebSocket 推送，不是前端轮询） |
| 登录限流 | 同 IP 1 分钟内登录 6 次 → 第 7 次返回 `429` |

## 五、W 级（明确不做，写下来是为了以后好拒绝）

| 不做 | 理由 |
|---|---|
| 拖拽排序任务 / 分类 | 前端工时黑洞，收益极低 |
| 主题切换、动画 | 同上 |
| 多人协作 / 任务分享 | 需要权限模型，是另一个项目 |
| 消息队列（RabbitMQ/Kafka） | TodoList 没有异步解耦场景，硬上会被问穿 |
| Elasticsearch | 数据量不够，`LIKE` 足够 |
| 分库分表 / 微服务 | 同上 |
| 移动端适配 / 小程序 | 本机演示，不需要 |
| 国际化 | 不需要 |
| 邮件 / 短信提醒 | 需要第三方服务，不划算 |
| OSS 文件存储 | 本机演示，本地磁盘够 |

> **W 级不是「做不到」，是「本期主动不做」。** 写进文档是为了第 8 天有人说「要不再加个 XX」时，你能指着这行说：这是 D1 定的。

## 七、已拍板的 4 件事

| # | 问题 | 决定 | 理由 |
|---|---|---|---|
| 1 | 分类和标签都做吗 | **都做** | 分类 = 一对多，标签 = 多对多。关系型数据库最核心的两种关系，只做一个少学一半 |
