## 二、数据模型决定（建表前必须定）

| 决策 | 选择 | 理由 |
|---|---|---|
| 时间精度 | `due_time DATETIME` | 精确到分是功能 8/9/11 的地基 |
| 分类 | **不做**，`todo` 表不建 `category_id` | 省 2h，少一条联调链 |
| 每日任务 | 表里**预留** `is_daily` + `last_done_date` 两列 | 建表时加上成本 0，做不做功能另说 |
| 完成时间 | **不单独存**，只存 `completed` 布尔 | 需求里没有"完成时间"的展示场景 |
| 软删除 | 不做，物理删除 | 需求里没有"回收站" |

> 预留两列但暂不实现，是真实项目的常见做法：**表结构一次改到位，功能可以分批上**。
> 代价是这两列暂时恒为 0/NULL，不影响任何逻辑。

## 四、演示脚本（5 分钟，提前排好）

1. 注册 → 登录（30 秒）
2. 建 3 条任务：一条今天 18:30 到期、一条昨天 18:00（造过期）、一条普通（1 分钟）
3. 展示：过期那条自动置顶标红（30 秒）
4. 勾选 / 编辑 / 删除各点一次（1 分钟）
5. 等 30 秒，弹窗提醒那条 1 分钟的任务（30 秒）
6. 换账号登录，证明看不到别人的数据（30 秒）
7. 讲链路：浏览器 → 拦截器 → Controller → Service → Mapper → MySQL → Result（2 分钟）
