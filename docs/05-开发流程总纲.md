# 05 · 开发流程总纲（15 天版）

> 本文取代 `docs/02-开发流程框架.md`（那份是 17.5h 版）。
> 适用：2 人、105h、32 个接口、12 个功能模块。
> 一句话：**前期两人串行把「做什么」钉死，后期两人并行各干各的。**

---

## 一、全景图

```
        ┌─────────── 双人串行（D1–D2）───────────┐
S0 需求冻结 → S1 选型环境 → S2 数据模型 → S3 接口契约
                                              │
                    ★ 分水岭：契约签完，两人分开跑
                    ┌─────────────────────────┴─────────────────────────┐
                    ↓ 你（后端）                                        ↓ 同伴（前端）
              S4  工程骨架                                        P1  脚手架 + 路由
              S5  认证权限                                        P2  登录 / 注册页
              S6  核心 CRUD   ───── 检查点① D5 ─────→            P3  任务主页（mock 数据）
              S7  领域复杂度                                      P4  日历 / 统计页
              S8  定时 + Redis ──── 检查点② D10 ────→            P5  接真接口
              S9  查询统计                                        P6  回收站 / 设置
              S10 实时推送
              S11 工程收尾
                    └─────────────────────────┬─────────────────────────┘
                                              ↓
                        S12 联调 → 部署 → 演示      ◀ 检查点③ D14
```

---

## 二、13 个步骤

| # | 步骤 | 干什么 | 产出物 | 天 | 谁 |
|---|---|---|---|---|---|
| S0 | 需求冻结 | 把「我想要」变成「做这几条、不做那几条」，每条写清验收标准 | 需求清单 v2（M/S/C/W 分级）+ 双人签字 | D1 上午 | 双人 |
| S1 | 选型 + 环境 | 定死版本号；每人机器验证能跑 | 版本清单 + 环境检查清单（**Redis 必须此时就 ping 通**） | D1 下午 | 双人 |
| S2 | 数据模型 | 画 ER 图，写 `schema.sql`，**一次建全 8 张表** | schema.sql + 字段说明 | D1 晚 | 后端 |
| S3 | 接口契约 ★ | 32 个接口的 URL / 方法 / 参数 / 响应 / 错误码全部写死 | 接口文档 v1（可导入 Apifox） | D2 全天 | 双人 |
| S4 | 工程骨架 | pom、启动类、统一响应、全局异常、ThreadLocal、拦截器、AOP | `/api/health` 返回统一格式；故意抛异常得 400 | D3 | 后端 |
| S5 | 认证权限 | 注册 / 登录 / 退出；JWT 签发校验；Redis 黑名单；登录限流 | Postman 走通「注册→登录→访问→退出→401」 | D4 | 后端 |
| S6 | 核心 CRUD | 任务 + 分类的增删改查 | **检查点①：第一次联调** | D5 | 后端 |
| S7 | 领域复杂度 | 标签（多对多）、子任务（一对多）、`@Transactional` | 能按标签筛、子任务进度正确 | D6 | 后端 |
| S8 | 定时 + 中间件 | 重复规则 + `@Scheduled` + 分布式锁；Redis 缓存 + 限流 | **检查点②：能演示自动生成 + 缓存命中** | D7–D8 | 后端 |
| S9 | 查询统计 | XML 动态 SQL、PageHelper、统计聚合、日历 | 多条件组合筛选正确、首页有数据 | D9–D10 | 后端 |
| S10 | 实时能力 | WebSocket 连接管理 + 到期推送 | 到点页面弹通知 | D11 | 后端 |
| S11 | 工程收尾 | AOP 操作日志、Excel 导出、单元测试、Swagger 定稿 | `mvn test` 全绿 | D12–D13 | 后端 |
| S12 | 联调部署 | 全流程走查、打包、排演 | 一个 jar 能起来 + 5 分钟讲稿 | D14–D15 | 双人 |

**前端线并行**：P1 脚手架（D4）→ P2 登录/注册（D5）→ P3 任务主页 mock（D6）→ P4 日历/统计（D7–D8）→ P5 接真接口（D9–D10）→ P6 回收站/设置（D11–D12）→ P7 打磨（D13）。

## 三、每一步「为什么不能跳」

| 步骤 | 跳过的后果 |
|---|---|
| S0 需求冻结 | 第 8 天开始漂移（"要不再加个 XX"），没有基线就无法拒绝，最后三天在赶新功能 |
| S1 环境验证 | Redis 拖到 D7 才发现连不上，一整天没了 |
| S2 数据模型 | 表结构是全项目**最贵的改动**：牵动实体、Mapper、Service、前端表单、接口文档五处 |
| S3 接口契约 | 前端只能等后端，两个人变一个人的效率；这是 S3 叫「分水岭」的原因 |
| S4 工程骨架 | 骨架没验收就写业务，业务代码里到处 try-catch，后面 30 个接口全部返工 |
| S5 认证权限 | 所有业务接口都依赖 `userId`，认证不通后面全堵 |
| S6 核心 CRUD | 攒着一起测，一天里冒出 20 个 bug，分不清是谁的错 |
| S10 实时能力 | 和别的混着做，WebSocket 的坑会吃掉两天 |
| S11 单元测试 | 最后没时间就只能不做，损失「工程能力」这块最值钱的加分 |

## 四、三个检查点（硬门禁）

| 检查点 | 时间 | 通过标准 | 不通过怎么办 |
|---|---|---|---|
| ① 第一次联调 | D5 下午 | 浏览器里能登录、看列表、增删改 | D6 全天只修这个，不加新功能 |
| ② 中期演示 | D10 下午 | 能演示「每日任务自动生成」「缓存命中」 | 立刻启动降级预案，砍 P2 页面 |
| ③ 全量走查 | D14 | 所有页面无阻塞，接口 100% 通 | D15 只修 P0 bug，演示脚本绕开问题点 |

**铁律：检查点不过，不许往下一步加新功能，只许修 bug。**

---

## 五、双人协作的三条规则

1. **S3 之前必须一起做**（需求、选型、建表、契约），这四件事任何一个人单独做都会在 D6 返工。
2. **S3 之后不许互相等**。前端用 mock 数据跑页面，后端按契约写接口，谁也别等谁。
3. **每周最后一次联调雷打不动**（D5、D10、D14）。联调不是「顺便」，是排进日程的事。

## 六、和「苍穹外卖」课程流程的对照

| 课程里 | 你的项目 | 区别 |
|---|---|---|
| 老师给需求文档 | 自己写 | **多这一步** |
| 老师给接口文档 | 自己设计 32 个 | **多这一步** |
| 老师给建表语句 | 自己画 ER 图 | **多这一步** |
| 照着视频敲 | 按契约自己实现 | 只有架构骨架可参考 |
| 没有单元测试 | 有 | **多这一步** |
| 没有部署 | 有 | 一样 |

**你比课程多出来的三件事——需求、契约、测试——恰好是面试最容易被问的三件事。**
