## 一、全局约定

### 1.1 基础信息

| 项 | 值 |
|---|---|
| 开发环境 Base URL | `http://localhost:8080` |
| 前端开发端口 | `http://localhost:5173`（Vite） |
| 接口统一前缀 | `/api` |
| 数据格式 | `application/json; charset=utf-8`（文件上传除外） |
| 时间格式 | `yyyy-MM-dd HH:mm`，如 `2026-11-20 18:30` |
| 时区 | 东八区 `Asia/Shanghai` |

### 1.2 统一响应体

**所有接口**返回同一个外壳：

```json
{ "code": 200, "msg": "ok", "data": {} }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 业务码，**与 HTTP 状态码保持一致**（见 1.3） |
| `msg` | string | 成功时为 `"ok"`，失败时为给用户看的中文提示 |
| `data` | any | 业务数据；无返回内容时为 `null` |

### 1.3 HTTP 状态码与业务码

**本项目的核心约定：HTTP 状态码真实反映语义，不用「永远 200」。**

| 场景 | HTTP | code | 谁处理 |
|---|---|---|---|
| 成功 | 200 | 200 | `then` |
| 参数校验失败 | 400 | 1001 | `catch` |
| 请求体不是合法 JSON | 400 | 1002 | `catch` |
| 未登录 / token 无效 | 401 | 2001 | `catch` → 跳登录页 |
| token 已过期 | 401 | 2002 | `catch` → 跳登录页 |
| 登录太频繁被限流 | 429 | 2003 | `catch` → 提示稍后再试 |
| 用户名或密码错误 | 401 | 2004 | `catch` → 提示 |
| 用户名已存在 | 400 | 3001 | `catch` → 提示 |
| 资源不存在 / 无权访问 | 404 | 3002 | `catch` → 提示 |
| 业务规则不允许 | 400 | 3003 | `catch` → 提示 |
| 服务器内部错误 | 500 | 5000 | `catch` → 提示 |

> **为什么 401 必须是真的 401**：前端用 axios，非 2xx 会自动进 `catch`。这样一个响应拦截器就能统一处理「登录失效 → 清 token → 跳登录页」。如果全部返回 200，前端要在每个 `then` 里判断 `code`，漏一个就是 bug。

> **为什么"无权访问"返回 404 而不是 403**：403 会告诉攻击者「这个 id 是存在的，只是不属于你」。返回 404 则连存在性都不暴露。用户数据隔离靠这一条。

### 1.4 认证

除标注「公开」的接口外，全部需要请求头：

```
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxIn0.xxxxx
```

- token 由登录接口下发，有效期 **7 天**
- token 放 `localStorage`，前端请求拦截器自动带上
- 退出登录后，该 token 立即失效（Redis 黑名单）
- 拦截器范围：`/api/**`，排除 `/api/auth/login`、`/api/auth/register`

### 1.5 URL 命名规范

- 资源用**复数**：`/api/todos`、`/api/categories`
- 层级**不超过 2 层**：`/api/todos/{id}/tags` ✅　`/api/users/1/todos/2/tags/3` ❌
- 动作使用**子资源 + 合适的 HTTP 方法**：
  - `PATCH /api/todos/{id}/toggle`（切换完成状态）
  - `POST /api/todos/{id}/repeat`（设为重复）
  - 不用 `POST /api/todos/toggle?id=1`、不用 `GET /api/todos/delete?id=1`

### 1.6 分页规范

**请求**

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `page` | int | 1 | 页码，**从 1 开始**（不是 0） |
| `pageSize` | int | 10 | 每页条数，最大 100 |

**响应**

```json
{ "list": [], "total": 57, "page": 1, "pageSize": 10 }
```

- `total` 是**总条数**，不是总页数
- 前端算总页数：`Math.ceil(total / pageSize)`
- 不分页的接口（如分类、标签）直接返回数组

### 1.7 通用错误示例

```json
{ "code": 1001, "msg": "标题不能为空", "data": null }
{ "code": 2001, "msg": "未登录或登录已过期", "data": null }
{ "code": 3002, "msg": "任务不存在", "data": null }
```

## 二、通用数据结构

这些结构会被多个接口复用，前后端都以本节为准。

### 2.1 `UserVO`

```json
{
  "id": 1,
  "username": "lsy",
  "nickname": "老王",
  "avatarUrl": "/api/files/12",
  "createdAt": "2026-11-14 10:00"
}
```

> **绝不返回 `password` 字段**，哪怕是密文。

### 2.2 `TodoVO`（最核心）

```json
{
  "id": 101,
  "title": "写周报",
  "description": "本周进度 + 下周计划",
  "priority": 1,
  "dueTime": "2026-11-20 18:30",
  "completed": false,
  "completedAt": null,
  "categoryId": 2,
  "categoryName": "工作",
  "categoryColor": "#409EFF",
  "parentId": null,
  "tags": [{ "id": 1, "name": "主线", "color": "#F56C6C" }],
  "childCount": 2,
  "doneChildCount": 1,
  "isTemplate": false,
  "templateId": null,
  "recurrenceType": null,
  "recurrenceDay": null,
  "overdue": true,
  "createdAt": "2026-11-14 10:00",
  "updatedAt": "2026-11-14 10:00"
}
```

| 字段 | 说明 |
|---|---|
| `priority` | 1=高 2=中 3=低。**数字越小越优先** |
| `dueTime` | 可为 `null`（无截止时间） |
| `overdue` | **后端算好返回**，前端直接用，不重复计算 |
| `childCount` / `doneChildCount` | 列表页显示「2/1」，详情页才拉子任务列表 |
| `isTemplate` | true 表示这是重复规则模板，**列表接口不返回模板行** |
| `tags` | 已按 id 排好序 |

> **`overdue` 为什么由后端算**：列表的排序 SQL 里已经用了 `due_time < NOW() AND completed = 0`。如果前端再算一遍，两处逻辑稍有偏差就会出现「排在第一行却没标红」。**同一个判断只能有一个真相来源。**
>
> 前端需要一个 30 秒定时器来刷新列表，但只用它**重新拉数据**，不自己算 `overdue`。

### 2.3 `CategoryVO`

```json
{ "id": 2, "name": "工作", "color": "#409EFF", "sortOrder": 0, "todoCount": 12 }
```

### 2.4 `TagVO`

```json
{ "id": 1, "name": "主线", "color": "#F56C6C", "todoCount": 5 }
```

### 2.5 `PageResult<T>`

```json
{ "list": [], "total": 0, "page": 1, "pageSize": 10 }
```

## 四、接口详情

### 1. 认证

---

#### 1.1 注册　`POST /api/auth/register`　· 公开

**请求体**

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `username` | string | 是 | 3–20 位，只允许字母、数字、下划线 |
| `password` | string | 是 | 6–20 位 |
| `nickname` | string | 否 | 最长 50 位，为空则用 username |

```json
{ "username": "lsy", "password": "123456", "nickname": "老王" }
```

**成功** `200`

```json
{ "code": 200, "msg": "ok", "data": { "id": 1, "username": "lsy", "nickname": "老王", "avatarUrl": null, "createdAt": "2026-11-14 10:00" } }
```

**失败**

| HTTP | code | msg |
|---|---|---|
| 400 | 1001 | 用户名长度需在 3–20 位之间 / 密码长度需在 6–20 位之间 |
| 400 | 3001 | 用户名已存在 |

**注意**：注册成功**不下发 token**，前端跳登录页。这样能让用户确认一次密码确实记住了。

---

#### 1.2 登录　`POST /api/auth/login`　· 公开

**请求体**

```json
{ "username": "lsy", "password": "123456" }
```

**成功** `200`

```json
{
  "code": 200,
  "msg": "ok",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9....",
    "expiresIn": 604800,
    "user": { "id": 1, "username": "lsy", "nickname": "老王", "avatarUrl": null }
  }
}
```

**失败**

| HTTP | code | msg |
|---|---|---|
| 401 | 2004 | 用户名或密码错误 |
| 429 | 2003 | 登录过于频繁，请 1 分钟后再试 |

> **用户名不存在和密码错误必须返回同一句提示**。分开提示等于告诉攻击者"这个用户名是存在的"，可以拿来撞库。
>
> **限流规则**：同一 IP 或同一用户名，1 分钟内最多 5 次失败，超出返回 429。用 Redis 的 `INCR` + `EXPIRE` 实现。

---

#### 1.3 退出登录　`POST /api/auth/logout`　· 需要认证

无请求体。

**成功** `200`

```json
{ "code": 200, "msg": "ok", "data": null }
```

> **后端要做的事**：把当前 token 的 jti 或原始串写入 Redis 黑名单，TTL 设为 token 剩余有效期。之后带着同一个 token 再访问任何接口都返回 401。
>
> 如果只让前端删 localStorage，那 token 在 7 天内仍然有效——在演示时被问「退出后旧 token 还能用吗」会答不上来。

### 4. 分类

---

#### 4.1 分类列表　`GET /api/categories`

无分页。**成功** `200`

```json
{
  "code": 200,
  "msg": "ok",
  "data": [
    { "id": 2, "name": "工作", "color": "#409EFF", "sortOrder": 0, "todoCount": 12 },
    { "id": 3, "name": "生活", "color": "#67C23A", "sortOrder": 1, "todoCount": 5 }
  ]
}
```

> 按 `sort_order ASC, id ASC` 排序。`todoCount` 由一条 `LEFT JOIN ... GROUP BY` 算出。
> **「未分类」不占一条记录**，它是 `categoryId = null` 的虚拟项，由前端自己拼在列表最前面。

---

#### 4.2 新增分类　`POST /api/categories`

**请求体**

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `name` | string | 是 | 1–30 位 |
| `color` | string | 否 | `#RRGGBB`，默认 `#409EFF` |
| `sortOrder` | int | 否 | 默认 0 |

**成功** `200` → `data` 为 `CategoryVO`

**失败**

| HTTP | code | msg |
|---|---|---|
| 400 | 1001 | 分类名不能为空 |
| 400 | 3003 | 分类名已存在 |

> 「分类名已存在」是**同一用户内**重复才算。两个人都有"工作"分类是正常的，靠 `UNIQUE(user_id, name)` 保证。

---

#### 4.3 修改分类　`PUT /api/categories/{id}`

请求体同 4.2（都可选）。

**成功** `200` → `data` 为更新后的 `CategoryVO`

**失败**：`404 / 3002` 分类不存在（**包括别人的分类**）

---

#### 4.4 删除分类　`DELETE /api/categories/{id}`

**成功** `200` → `data: null`

**行为**：该分类下所有任务的 `category_id` 置为 `NULL`（变成"未分类"），**任务本身不删**。

**失败**：`404 / 3002` 分类不存在

> **不要用 CASCADE 删任务**。用户删一个分类，结果 12 个任务全没了——这是会造成实际损失的 bug。
>
> 实现上分两条 SQL 在一个 `@Transactional` 里：
> ```sql
> UPDATE todo SET category_id = NULL WHERE category_id = ? AND user_id = ?;
> DELETE FROM category WHERE id = ? AND user_id = ?;
> ```

### 6. 任务（核心）

---

#### 6.1 任务列表　`GET /api/todos`

**查询参数**

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `status` | string | `all` | `all` / `active` / `completed` / `overdue` |
| `keyword` | string | — | 标题模糊搜索 |
| `categoryId` | long | — | 按分类筛选；传 `0` 表示"未分类" |
| `tagId` | long | — | 按标签筛选（走中间表） |
| `priority` | int | — | 1/2/3 |
| `dueFrom` | string | — | `yyyy-MM-dd`，截止时间 ≥ 该日 |
| `dueTo` | string | — | `yyyy-MM-dd`，截止时间 ≤ 该日 |
| `page` | int | 1 | |
| `pageSize` | int | 10 | 最大 100 |
| `sort` | string | `due` | `due` / `priority` / `created` |

**成功** `200`

```json
{
  "code": 200,
  "msg": "ok",
  "data": {
    "list": [ /* TodoVO 数组 */ ],
    "total": 57, "page": 1, "pageSize": 10
  }
}
```

**默认排序（必须严格按这个来）**

```sql
ORDER BY t.completed ASC,                                            -- 未完成在前
         CASE WHEN t.completed = 0 AND t.due_time < NOW() THEN 0 ELSE 1 END ASC,  -- 已过期最前
         t.priority ASC,                                             -- 高 > 中 > 低
         t.due_time IS NULL, t.due_time ASC,                         -- 无截止时间的排最后
         t.id DESC
```

> **为什么用 `CASE WHEN` 而不是直接比 `due_time`**：直接在 `ORDER BY` 里写 `t.due_time < NOW()` 在 MySQL 里返回 0/1，能用，但 `completed = 1` 的任务也会被算成"过期"顶到前面。必须显式排除已完成任务。

**筛选条件 SQL 片段**

```sql
WHERE t.user_id = #{userId}
  AND t.deleted_at IS NULL
  AND t.is_template = 0              -- 模板行不进列表
  AND t.parent_id IS NULL            -- 列表只显示顶层任务，子任务在详情里
  -- status = active   → AND t.completed = 0
  -- status = completed→ AND t.completed = 1
  -- status = overdue  → AND t.completed = 0 AND t.due_time < NOW()
  -- keyword          → AND t.title LIKE CONCAT('%', #{keyword}, '%')
  -- categoryId > 0   → AND t.category_id = #{categoryId}
  -- categoryId = 0   → AND t.category_id IS NULL
  -- tagId            → AND EXISTS (SELECT 1 FROM todo_tag tt WHERE tt.todo_id = t.id AND tt.tag_id = #{tagId})
  -- priority         → AND t.priority = #{priority}
  -- dueFrom/dueTo    → AND t.due_time BETWEEN #{dueFrom} AND #{dueTo}
```

---

#### 6.2 新增任务　`POST /api/todos`

**请求体**

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `title` | string | 是 | 1–200 位 |
| `description` | string | 否 | 最长 1000 |
| `priority` | int | 否 | 1/2/3，默认 2 |
| `dueTime` | string | 否 | `yyyy-MM-dd HH:mm` |
| `categoryId` | long | 否 | 必须属于当前用户 |
| `parentId` | long | 否 | 子任务用，见 6.8 |
| `tagIds` | long[] | 否 | 标签 id 数组 |

```json
{
  "title": "写周报",
  "description": "本周进度",
  "priority": 1,
  "dueTime": "2026-11-20 18:30",
  "categoryId": 2,
  "tagIds": [1, 3]
}
```

**成功** `200` → `data` 为新建的 `TodoVO`

**失败**

| HTTP | code | msg |
|---|---|---|
| 400 | 1001 | 标题不能为空 / 优先级只能是 1、2、3 |
| 400 | 3003 | 分类不存在 |
| 400 | 3003 | 子任务不能再有子任务 |

> `tagIds` 一次性写入 `todo_tag`，整个新增在**一个事务**里。

---

#### 6.3 任务详情　`GET /api/todos/{id}`

**成功** `200` → `TodoVO`（含 `tags`、`childCount`、`doneChildCount`）

**失败**：`404 / 3002` 任务不存在

---

#### 6.4 修改任务　`PUT /api/todos/{id}`

请求体同 6.2（全字段可选，传了才改）。

**成功** `200` → 更新后的 `TodoVO`

**失败**：`404 / 3002`

> **注意 `tagIds` 的语义**：传了 `tagIds` 就**整体覆盖**（先删后插），没传就保持原样。不要做成"增量添加"，否则前端没法取消某个标签。

---

#### 6.5 删除任务　`DELETE /api/todos/{id}`

**成功** `200` → `data: null`

**行为**：**软删除**，`UPDATE todo SET deleted_at = NOW()`。任务进回收站，可在 30 天内恢复。

> 软删除的 `user_id` 校验不能省：`WHERE id = ? AND user_id = ? AND deleted_at IS NULL`。影响行数为 0 就返回 404。

---

#### 6.6 切换完成状态　`PATCH /api/todos/{id}/toggle`

无请求体。

**成功** `200` → 更新后的 `TodoVO`

**行为**

```
completed 0 → 1：completed = 1, completed_at = NOW()
completed 1 → 0：completed = 0, completed_at = NULL
```

**失败**：`404 / 3002`

> **`completed_at` 必须在同一句 UPDATE 里写**：`SET completed = 1 - completed, completed_at = IF(completed = 0, NOW(), NULL)` —— 注意 MySQL 的 `SET` 是从左到右求值的，所以 `completed_at` 的判断要用**改之前**的值。安全写法是先查再改，或用 `CASE WHEN completed = 0 THEN NOW() ELSE NULL END` 写在 `completed` 前面。
>
> **连点两次必须回到原状**，这是幂等性测试用例。

---

#### 6.7 设置任务标签　`PUT /api/todos/{id}/tags`

**请求体**

```json
{ "tagIds": [1, 3] }
```

**成功** `200` → `data: null`

**行为**：整体覆盖。先 `DELETE FROM todo_tag WHERE todo_id = ?`，再批量插入。传空数组就是清空标签。

**失败**：`404 / 3002`

### 8. 重复规则

---

#### 8.1 设为重复任务　`POST /api/todos/{id}/repeat`

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `recurrenceType` | string | 是 | `DAILY` / `WEEKLY` / `MONTHLY` |
| `recurrenceDay` | string | 条件 | `WEEKLY` 传 `1`–`7`（1=周一）；`MONTHLY` 传 `1`–`31`；`DAILY` 不传 |

```json
{ "recurrenceType": "WEEKLY", "recurrenceDay": "1" }
```

**成功** `200` → `TodoVO`（`isTemplate = true`）

**行为**

1. 把这条任务变成**模板**：`is_template = 1`，写入 `recurrence_type`、`recurrence_day`
2. 立即生成**今天到该截止日的实例**（至少生成今天一条，如果今天符合规则）
3. `last_generated` 记为今天

**失败**

| HTTP | code | msg |
|---|---|---|
| 400 | 1001 | 重复类型只能是 DAILY/WEEKLY/MONTHLY |
| 400 | 1001 | WEEKLY 必须指定 1–7 |
| 400 | 3003 | 子任务不能设为重复任务 |

---

#### 8.2 取消重复　`DELETE /api/todos/{id}/repeat`

**成功** `200` → `data: null`

**行为**：模板行 `is_template = 0`、清空 `recurrence_*`。**已生成的实例保留**（用户可能已经完成了几个）。

**成功** `200` → `PageResult<TodoVO>`（只查 `template_id = {id}` 的行）

### 13. WebSocket 提醒通道

**连接地址**

```
ws://localhost:8080/ws/todo?token=<JWT>
```

> 浏览器的 WebSocket API **不能自定义请求头**，所以 token 只能放 query 参数。这是 WebSocket 鉴权的常见妥协。服务端在握手阶段解析并校验，失败直接拒绝连接。

**服务端推送格式**

```json
{
  "type": "TODO_DUE",
  "data": { "todoId": 101, "title": "写周报", "dueTime": "2026-11-20 18:30", "minutesLeft": 0 }
}
```

| type | 含义 |
|---|---|
| `TODO_DUE` | 任务到期了 |
| `TODO_REMIND` | 提前提醒（按用户设置的 `remindAheadMinutes`） |

**心跳**

- 客户端每 30 秒发一次 `{"type":"PING"}`
- 服务端回 `{"type":"PONG"}`
- 服务端 90 秒没收到任何消息就断开
