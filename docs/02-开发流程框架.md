## 二、每个阶段在干什么

### S0 · 需求冻结（0.5h，双人）

**干什么**：把"想做"和"能做"分开，写死这一版做什么。

**产出**：一张表，四列——功能 / 必须(M) / 应该(S) / 可以(C) / 不做(W)。

| 功能 | 级别 | 说明 |
|---|---|---|
| 注册 / 登录 | M | 没有它，数据隔离讲不了 |
| Todo 增删改查 | M | 主体 |
| 截止时间精确到分 | M | 后面 3 个功能的地基 |
| 过期置顶标红 | M | 演示肉眼可见 |
| 到期弹窗 | S | 演示"哇"点 |
| 每日固定任务 | S | 体现设计能力 |
| 分类管理 | C | 时间够才做 |
| 下拉刷新（手势） | W | PC 上没效果 |
| Redis / Docker / 微服务 | W | 明确不碰 |

**为什么不能跳**：新手最典型的翻车方式是"边做边加需求"，两天半里加 3 个需求 = 一定做不完。冻结的意思是：**中途想加，先写进"下一版"清单，不许直接动代码。**

**最容易犯的错**：把"分类管理"当成必须。它只是把 Todo 分个组，演示价值低、联调成本高（多一整套 CRUD），砍它。

---

### S1 · 技术选型 + 环境（0.5h）

**干什么**：把版本号写死，跑通一次空构建。

**产出**：
- `pom.xml` 定稿（Spring Boot 2.7.18 / MyBatis 2.3.2 / PageHelper / springdoc 1.7.0 / jjwt 0.11.5）
- `mvn -q clean package` 或 `mvn spring-boot:run` 成功一次
- MySQL 8 能连上，`SELECT VERSION();` 有结果

**为什么不能跳**：Maven 首次下载依赖在国内网络可能卡 10–20 分钟，甚至失败。这个坑必须**在写第一行业务代码之前**踩掉，否则你会错怪自己的代码。

**验收**：删掉 `~/.m2` 里的某个依赖再下一次也能成功（说明镜像配好了）。

---

### S2 · 建表（1.5h）

**干什么**：先定数据结构，再写任何 Java 代码。

**产出**：`src/main/resources/schema.sql`

```sql
CREATE TABLE todo (
    id            BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id       BIGINT       NOT NULL,
    title         VARCHAR(100) NOT NULL,
    description   VARCHAR(500),
    due_time      DATETIME,              -- ← 精确到分，不是 DATE
    priority      TINYINT      NOT NULL DEFAULT 1,   -- 0低 1中 2高
    completed     TINYINT(1)   NOT NULL DEFAULT 0,
    is_daily      TINYINT(1)   NOT NULL DEFAULT 0,   -- ← 每日固定任务
    last_done_date DATE,                             -- ← 每日任务"哪天完成过"
    created_at    DATETIME     NOT NULL,
    updated_at    DATETIME     NOT NULL,
    INDEX idx_todo_user (user_id),
    INDEX idx_todo_due  (due_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**三条自检**（过不了就是表设计错了，别往下走）：

1. 能不能用**一条 SQL** 查出"今天我要做的所有事"（普通任务 + 每日任务）？
2. "已逾期"能不能直接用 `due_time < NOW() AND completed = 0` 表达？
3. 每日任务的状态能不能只靠 `last_done_date` 算出来，不建第二张表？

**为什么不能跳**：表错了，Entity / DTO / Mapper / Service / 前端全部返工。这是整个项目**唯一**返工成本指数级的地方。

---

### S3 · 接口契约（1.5h，双人）★ 最重要的 1.5 小时

**干什么**：把"前端要什么、后端给什么"写成文档，**双方签字**（口头也行，但要一起过一遍）。

**产出**：`docs/03-接口文档.md`，包含三部分。

**① 统一响应格式（先定这个，所有接口都一样）**

```json
{ "code": 200, "msg": "success", "data": ... }
```

| code | 含义 | 前端动作 |
|---|---|---|
| 200 | 成功 | 取 `data` |
| 400 | 参数/业务错误 | `ElMessage.error(msg)` |
| 401 | 未登录/过期 | 清 token，跳登录页 |
| 500 | 服务端异常 | 提示"系统繁忙" |

**② 接口清单（9 个，先写全，再实现）**

| # | 方法 | 路径 | 入参 | 出参 | 归属 |
|---|---|---|---|---|---|
| 1 | POST | `/api/auth/register` | `{username,password,nickname}` | `{id,username}` | 你 |
| 2 | POST | `/api/auth/login` | `{username,password}` | `{token,user}` | 你 |
| 3 | GET | `/api/todos` | `?status=all\|active\|completed&keyword=` | `TodoVO[]` | 你 |
| 4 | POST | `/api/todos` | `{title,description,dueTime,priority,isDaily}` | `TodoVO` | 你 |
| 5 | PUT | `/api/todos/{id}` | 同上 | `TodoVO` | 你 |
| 6 | DELETE | `/api/todos/{id}` | — | `null` | 你 |
| 7 | PATCH | `/api/todos/{id}/toggle` | — | `TodoVO` | 你 |
| 8 | GET | `/api/todos/stats` | — | `{total,active,doneToday,overdue}` | 你 |
| 9 | GET | `/api/todos/today` | — | `TodoVO[]`（含每日任务） | 你 |

**③ 一个完整的接口样例（其余照抄格式）**

```markdown
### 3. 查询任务列表
GET /api/todos?status=active&keyword=报告
Header: Authorization: Bearer <token>

响应 200:
{
  "code": 200,
  "msg": "success",
  "data": [
    {
      "id": 12,
      "title": "写周报",
      "description": "本周进度",
      "dueTime": "2026-11-14 18:00",
      "priority": 2,
      "completed": false,
      "isDaily": false,
      "overdue": true          // ← 后端算好直接给前端，别让前端自己算
    }
  ]
}
错误 401: {"code":401,"msg":"未登录或登录已过期","data":null}
```

**为什么不能跳**：这是**双人项目的唯一解耦点**。没有它，前端只能等你写完才能动，17.5h 就变成 35h 串行。

**最容易犯的错**：字段名对不上（`dueTime` vs `dueDate`）、时间格式对不上（`"2026-11-14 18:00"` vs ISO `T` 分隔）、`data` 是数组还是对象对不上。**这三个错，联调时会吃掉你 2 小时。**

**签字动作**：让同伴拿这份文档，**不看后端代码**，把 axios 封装和一个页面的列表渲染写出来。写不出来就说明文档没写清，回去补。

---

### S4 · 后端骨架（2.5h）

**干什么**：只搭"壳"，不写业务。目标是让一个假接口能跑通全链路。

**顺序不能乱**（每一步都要能单独跑起来）：

| 步 | 做什么 | 验收 |
|---|---|---|
| 1 | `pom.xml` + 启动类 + `application.yml` | `mvn spring-boot:run` 起得来 |
| 2 | `GET /api/health` 返回 `"ok"` | 浏览器能打开 |
| 3 | `Result<T>` + `ResultCode` + `@RestControllerAdvice` | 故意抛异常，返回 JSON 不是错误页 |
| 4 | 连 MySQL + 一个 `UserMapper.findById` | 日志能看到 SQL，返回 null 不报错 |
| 5 | `@Valid` 校验试一次 | 传空 username 返回 400 |

**为什么不能跳**：这 5 步是"环境验证"。如果第 5 步之前就写业务，后面任何报错你分不清是业务写错还是环境没配好。

---

### S5 · 后端业务（5h）

**干什么**：一个接口一个循环，不许攒着一起写。

**固定的循环（每个接口都走一遍）：**

```
写 Mapper（SQL）→ 写 Service（业务+校验）→ 写 Controller（收参+返回）
→ curl 测一次 → 通过 → git commit
```

**顺序（按依赖）：**

| 顺序 | 接口 | 时长 | 为什么排这儿 |
|---|---|---|---|
| 1 | 注册 | 40min | 第一次完整走"校验→业务→落库" |
| 2 | 登录 + 发 token | 40min | 发 token |
| 3 | JWT 拦截器 | 40min | 把 userId 送到 Service，这是最容易讲不清的一段 |
| 4 | 列表查询 | 40min | SQL 最复杂，先啃硬的 |
| 5 | 新增 | 30min | |
| 6 | 编辑 | 30min | 和新增几乎一样，复用思路 |
| 7 | 勾选 | 20min | |
| 8 | 删除 | 20min | |
| 9 | 统计 | 20min | 一条聚合 SQL |
| 10 | 每日任务改造 | 40min | 依赖 4/5/7，放最后 |

**纪律**：每完成一个接口，**立刻**用 curl 或 Postman 调一次。不要"全写完再测"——那时候报错你根本不知道是哪一个。

---

### S6 · 改进功能（2.5h，后端侧）

只做后端相关的部分，前端部分在 S9。

| 功能 | 后端要做的 | 时长 |
|---|---|---|
| 5 截止时间精确到分 | 实体/DTO/Mapper 改 `LocalDateTime`（S2 已建好 `due_time`，这里主要是 Java 侧） | 1h |
| 1 过期置顶标红 | 列表 SQL 加排序 + 在 VO 里加 `overdue` 布尔字段 | 40min |
| 4 每日固定任务 | `/api/todos/today` 合并查询 + toggle 分支 | 1h |

**注意**：`overdue` 一定要**后端算好返回**，不要让前端拿 `dueTime` 自己比。原因：前端和后端的"现在"可能差几秒，而且前端改判断逻辑要改两处。这是"接口设计"的一个真实取舍，演示时可以讲。

---

### S7–S9 · 前端线（同伴，约 12h）

不展开，只说**你必须懂的三个接口点**：

1. `baseURL: '/api'`，Vite `proxy` 把 `/api` 转到 `localhost:8080`。
2. 请求拦截器塞 `Authorization: Bearer ${token}`。
3. 响应拦截器：`code===401` 就清 token 跳登录；`code!==200` 弹 `msg`。

**你在这条线上的责任**：契约不变。要改接口，先改 `docs/03-接口文档.md`，再通知，再改代码。

---

### S10 · 联调（2h，双人）

**干什么**：把前端从假数据切到真接口。

**固定顺序**（从简到繁，每一步过了再下一步）：

```
登录 → 列表（空）→ 新增 → 列表（有数据）→ 勾选 → 编辑 → 删除 → 统计 → 改进功能
```

**联调 80% 的时间花在这 4 个错上：**

| 现象 | 真正的原因 |
|---|---|
| 列表空白，但 Postman 有数据 | `res.data.data` 解包层级错 |
| 一直 401 | axios 拦截器没塞 token，或拦截器路径没排除 `/api/auth/**` |
| CORS 报错 | 后端 `allowedOrigins` 没写 `http://localhost:5173` |
| 时间显示成 `[2026,11,14,18,0]` | 后端缺 `@JsonFormat` |

**纪律**：联调时**后端不许改接口形状**。要改就停下来，两个人一起改文档。

---

### S11 · 部署（1h）

**干什么**：证明它能脱离 IDE 独立跑。

```powershell
# 1. 前端打包（同伴）
cd frontend; npm run build

# 2. 产物拷进后端 static
Copy-Item -Recurse dist\* ..\src\main\resources\static\

# 3. 打 jar
mvn clean package -DskipTests

# 4. 跑
java -jar target\todolist-1.0.0.jar
```

**验收**：关掉 IDEA，命令行启 `java -jar`，浏览器打开 `http://localhost:8080` 全流程可用。

**为什么不能跳**：IDE 能跑 ≠ 能交付。这一步会暴露"配置文件没打进 jar""静态资源路径错"这类问题，早发现 30 分钟，晚发现 2 小时。

---

### S12 · 演示 + 复盘（0.5h）

**干什么**：练一遍 5 分钟讲稿，然后 git 提交。

**讲稿结构（5 分钟）**：

1. 30 秒：做什么的，给谁用
2. 1 分钟：浏览器点一遍主流程
3. 2 分钟：一次请求的完整链路（浏览器 → 拦截器验 token → Controller → Service → Mapper → MySQL → Result → JSON）
4. 1 分钟：三个技术点各一句（JWT 为什么无状态、统一异常为什么一个出口、`overdue` 为什么后端算）
5. 30 秒：没做完的 + 下一步

## 四、砍单预案（按触发时间）

| 触发点 | 如果卡在 | 立刻砍成 |
|---|---|---|
| D1 上午结束 | Maven 依赖下不下来 | 换阿里云镜像；仍不行 → 问同学要 `~/.m2` 备份 |
| D1 中午 | MySQL 连不上 | 换 H2 内存库 + `schema.sql` 自动建表，**演示时说明是内存库** |
| D1 结束 | JWT 签发/解析不通 | token 换成 UUID + 内存 Map，砍掉"无状态"这个讲点 |
| D2 中午 | 列表查询 SQL 写不出 | 先 `SELECT *` 全量返回，筛选挪到内存里 `stream().filter()`，**但要能讲清为什么这样不对** |
| D2 结束 | Todo CRUD 没做完 | 只保 新增 / 列表 / 勾选 / 删除 四个 |
| D3 上午 | 联调不通 | 前端降级为静态假数据 + 后端用 Swagger/Postman 演示，讲清"哪部分是后端" |

**底线**：宁可交一个**小而完整、每行都能解释**的版本，也不要一个跑不起来的大摊子。

---

## 五、双人协作的三条军规

1. **接口文档是唯一契约**。改接口 = 先改文档 + 通知对方 + 再改代码。顺序错了就返工。
2. **每天收工前 10 分钟对齐**：今天完成了什么、明天第一件事是什么、有没有接口要改。
3. **前端先用假数据**。S3 契约签完，同伴立刻可以开工，不需要等你后端跑通。

## 六、这份流程和你学过的苍穹外卖怎么对上

| 这个流程 | 苍穹外卖里对应什么 | 你实际在练什么 |
|---|---|---|
| S2 建表 | 第一天建库建表 | 数据建模 |

| S4 骨架 | 项目初始化 | 环境排查 |
| S5 业务 | 一天一个模块 | 分层落地 |
| S6 改进 | 需求变更 | 在已有代码上加功能 |
| S10 联调 | 前后端对接 | 契约验证 |
| S11 部署 | 打包上线 | 交付 |

**教程里你缺的那一课，就是 S3。** 苍穹外卖的接口文档是现成的，你从没自己设计过。这一步做完，你才算真的会"开发"，而不只是"实现"。
